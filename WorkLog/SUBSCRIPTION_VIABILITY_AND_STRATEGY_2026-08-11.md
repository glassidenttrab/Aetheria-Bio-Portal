# 구독 결제 현실성 분석 및 전략 계획
**작성일**: 2026-08-11
**작성 배경**: 실시간 유전자 검색(UniProt/AlphaFold/ChEMBL/OpenTargets/PubMed/ClinicalTrials.gov) 연동 완료 후, "지금 이대로 구독 결제를 유도할 수 있는가"를 놓고 나눈 대화를 정리. Gemini에게 물어봤을 때 "가능하다"고 답했던 것과 실제 구현 가능 범위 사이의 간극을 확인한 직후 작성.

---

## 1. 결론 먼저

**지금 이대로는 구독할 이유가 약합니다.** 진짜 가치 있는 기능(실시간 검색)은 로그인/결제 여부와 무관하게 누구나 무제한 무료이고, 유료로 막힌 기능(17개 큐레이션 리포트)은 여전히 가짜 데이터이기 때문입니다.

하지만 **서비스 자체가 무의미하다는 뜻은 아닙니다.** 오늘 실제로 연동된 6개 실시간 데이터베이스, 서버 검증 결제, 인증/권한 시스템은 진짜 자산입니다. 문제는 "무엇에 돈을 받을 것인가"를 다시 정의하지 않은 채 기능만 늘려온 것입니다. 이 문서는 그 재정의를 위한 선택지를 정리합니다.

---

## 2. 현재 자산 재고 조사 (무엇이 진짜이고 무엇이 가짜인가)

### ✅ 진짜로 작동하는 것 (오늘 기준)

| 자산 | 설명 |
|---|---|
| 실시간 유전자 검색 | UniProt·AlphaFold DB·ChEMBL·Open Targets·PubMed·ClinicalTrials.gov 6개 공개 API 실시간 연동. 10개 부서 어디서든 임의의 유전자 검색 가능 |
| 3D 구조 뷰어 | AlphaFold DB 실제 구조 파일을 3dmol.js로 렌더링, pLDDT 신뢰도 실제 표시 |
| 결제 서버 검증 | PayPal 주문을 서버가 직접 캡처·금액 대조 후 권한 부여(클라이언트 자체 승인 불가) |
| 인증/권한 | Supabase Auth + RLS로 본인 데이터만 접근, 관리자 권한 컬럼 단위 잠금 |
| 서버 쿼터 | 로그인 계정 기준 서버에서 원자적으로 쿼터 체크·차감(브라우저 종속 아님) |
| 구독 만료 자동화 | Vercel Cron으로 매일 만료된 구독 자동 강등 |
| 감사 로그 | 실제 사용된 스킬명(uniprot-database 등) 기준으로 관리자 콘솔에 기록 |
| 8개 언어 UI | 전체 기능 다국어 지원 |

### 🔴 여전히 가짜인 것

| 자산 | 설명 |
|---|---|
| 17개 큐레이션 "AI 표적 스캐너" 리포트 | hitCandidates(SMILES, IC50, 특허FTO, 시장가치)가 정적 하드코딩 데이터. 부서당 1~2개, 전체 17개뿐 |
| 특허 FTO 판단 | 애초에 무료 공개 API로는 절대 만들 수 없는 값(유료 특허 DB + 변리사 판단 필요) |
| 시장가치 추정 | 마찬가지로 유료 시장조사 데이터(Evaluate Pharma 등) 없이는 불가능 |

### ⚠️ 핵심 문제: 가치와 과금의 불일치

```
진짜 가치 있는 것(실시간 검색)  →  무료, 무제한
가짜인 것(17개 리포트)         →  유료 쿼터로 막혀 있음
```

이러니 "돈을 내면 뭘 더 받는가?"에 대한 답이 "가짜 리포트를 더 많이 볼 수 있다"가 되어버립니다. 그리고 이 실시간 검색 자체도 ChatGPT/Gemini 같은 범용 AI 챗봇에게 물어보면 비슷한 수준의 정보를 무료로 얻을 수 있어(직접 확인함), 검색 결과 자체는 강한 차별점이 아닙니다.

## 3. 이 서비스가 챗봇과 다른 점 (있다면)

| 항목 | 범용 AI 챗봇(Gemini 등) | Aetheria Bio Portal |
|---|---|---|
| 정보 출처 | LLM 내부 지식(할루시네이션 위험) | 실제 DB 실시간 조회(accession/PMID/NCT ID로 검증 가능) |
| 신뢰성 | 매번 다를 수 있음, 출처 불명확 | 동일 질의 시 항상 같은 실제 데이터, 출처 링크 제공 |
| 이력 관리 | 대화가 사라짐 | 관심 표적 보관함, 감사 로그로 영구 기록 |
| 워크플로우 통합 | 없음 | (아직 없음 — 잠재적 확장 지점) |
| 팀/조직 단위 사용 | 없음 | (아직 없음 — 잠재적 확장 지점) |

즉 **"정보를 처음 찾아주는 것"으로는 챗봇을 이길 수 없지만, "찾은 정보를 신뢰성 있게 기록·관리·공유하는 것"은 챗봇이 못 하는 영역**입니다. 아래 시나리오들은 대부분 이 지점을 파고듭니다.

---

## 4. 가능한 시나리오 분석

### 시나리오 A — B2B 컴플라이언스/감사 추적 (제약사·바이오텍 R&D 부서 대상)

**아이디어**: 이미 만들어둔 `skill_audit_logs`를 "누가 언제 무엇을 조회했는지"의 규제 문서화 도구로 발전시킴. 제약사 R&D는 실제로 이런 감사 이력이 필요한 경우가 있음(내부 검토, 특허 출원 시 선행 조사 증빙 등).

- **강점**: 챗봇이 절대 못 주는 것(영구 기록, 조직 단위 권한, 내보내기). 이미 인프라 일부 존재.
- **약점**: "감사 로그 몇 줄"과 "실제 규제 대응 문서(예: 21 CFR Part 11 수준 전자기록)" 사이 간극이 큼. 실제 제약사에 팔려면 보안 인증(SOC2 등)·계약·영업이 필요 — 솔로 개발자가 혼자 감당하기 어려운 영역.
- **현실성**: 낮음~중간. "언젠가"는 맞는 방향이지만 지금 규모로는 시기상조.

### 시나리오 B — 니치 버티컬 집중 (10개 부서 → 1~2개로 좁히고 깊게)

**아이디어**: 10개 부서에 17개 큐레이션 표적을 얇게 펼치는 대신, 대표님이 실제 관심/전문성이 있는 한 분야(예: 안티에이징/노화 세놀리틱스 — 기존 "Neuro-Rejuve" 네이밍과 SenoScan 기능명에서 이미 그 방향성이 보임)에 집중. 그 한 분야만큼은 특허FTO·시장가치까지 **직접 조사해서 진짜 데이터로 채움**.

- **강점**: 솔로 개발자가 혼자 감당 가능한 범위. "이 분야만큼은 진짜"라는 좁지만 진실한 차별점 확보 가능. 좁은 타깃(소규모 바이오텍 투자자, 창업 준비자)은 챗봇의 일반론적 답변보다 큐레이션된 전문 콘텐츠에 기꺼이 돈을 낼 유인이 있음.
- **약점**: "전신 10대 의학 분야" 마케팅 문구를 스스로 축소해야 함 — 지금까지의 포지셔닝과 충돌. 실제 조사(직접 특허 검색, 시장 데이터 확보)는 대표님의 시간 투입이 필요함(코드로 자동화 불가).
- **현실성**: 중간~높음. 가장 "정직하게 돈을 받을 수 있는" 경로.

### 시나리오 C — 워크플로우 도구화 (저장·비교·알림)

**아이디어**: 검색 자체는 계속 무료로 열어두고, 그 위에 챗봇이 못 하는 도구를 얹음 — 여러 표적을 저장해 비교표로 보기, 관심 표적에 새 임상시험/논문이 뜨면 알림, 팀과 보관함 공유.

- **강점**: 기존 관심 표적 보관함 기능을 자연스럽게 확장. 검색 자체의 신뢰성 문제(챗봇과 경쟁)를 피해감 — "찾아주는 것"이 아니라 "관리해주는 것"으로 가치 이동.
- **약점**: 알림/구독형 워크플로우 도구는 개발 범위가 크고(백그라운드 작업, 이메일 발송 등), 지금 아키텍처(Vercel 서버리스)로는 주기적 크롤링·알림 인프라를 새로 만들어야 함.
- **현실성**: 중간. 기술적으로는 가능하나 시나리오 B보다 개발 공수가 큼.

### 시나리오 D — 완전 무료 전환 + 다른 수익 모델(애드센스 등)

이미 논의했듯 **비추천**. 니치 도구 특성상 세션당 페이지뷰가 적어 광고 수익이 미미하고, 향후 B/C 시나리오로 발전시킬 신뢰도를 스스로 깎아먹음.

### 시나리오 E — 사업 정리 / 포트폴리오 전환

**아이디어**: 구독 수익화를 접고, 실제 작동하는 기술 데모(포트폴리오/이력서용)로 포지션을 바꿈. 인프라 투자가 헛되지 않으려면 최소한 이 정도 가치는 항상 남음.

- **현실성**: 항상 가능한 최후 대안. 다만 지금 판단하기엔 이릅니다 — 시나리오 B를 먼저 소규모로 시도해보고 반응을 본 뒤 결정해도 늦지 않습니다.

## 5. 권고안

**1순위: 시나리오 B(니치 집중) 소규모 시범 적용**

이유:
- 솔로 개발자 리소스로 실제 완수 가능한 유일한 시나리오
- "전신 10대 의학"이라는 넓지만 얕은 포지셔닝을 "이 분야는 진짜"라는 좁지만 깊은 포지셔닝으로 바꾸는 것 — 지금 상태(넓고 얕음)보다 신뢰도가 훨씬 높아짐
- 나중에 B2B(시나리오 A)나 워크플로우 도구(시나리오 C)로 확장할 때도, "이 한 분야는 우리가 최고"라는 근거가 있어야 설득력이 생김

**구체적 다음 단계 (제안, 결정은 대표님 몫)**:
1. 10개 부서 중 진짜 깊게 팔 분야 1개 선정(대표님의 관심/네트워크/전문성 기준)
2. 그 분야의 표적 목록을 5~10개 정도로 추리고, 특허FTO·시장 관련 정보를 대표님이 직접(또는 유료 특허 검색 서비스 1회성 이용으로) 조사해 실제 데이터로 교체
3. 나머지 9개 부서는 "베타/준비 중" 또는 실시간 검색만 제공하는 상태로 명확히 라벨링(과장 마케팅 문구 정리)
4. 그 좁은 타깃(예: 세놀리틱스 관심 투자자/연구자)에게 소규모로 유료 전환 테스트

이 방향에 동의하시면, 어느 부서/분야로 좁힐지부터 정하는 게 다음 순서입니다.

- **배경 및 원인**: 
  - Enterprise B2B 콘솔 모달을 열었을 때, 최상위 Overlay의 CSS 레이아웃(`display: flex; align-items: center;`) 한계로 인해, 디바이스 뷰포트 높이가 낮거나 스크롤이 발생할 때 모달의 상단 헤더 타이틀과 닫기(`X`) 버튼이 뷰포트 상단 영역(Negative Y offset) 밖으로 넘어가 잘려 보이지 않는 버그가 지적됨.

  - **효과**: 넉넉한 뷰포트에서는 화면 수직 중앙에 예쁘게 배치되고, 좁은 화면이나 오버플로우 발생 시에는 상단 32px 위치에 안전하게 고정되어 헤더 타이틀 및 닫기 버튼이 1px도 잘리지 않도록 레이아웃 완벽 개선.

### 11. 인증을 Supabase Auth로 완전 통합 + RLS(Row Level Security) 실제 적용
- **배경**: 10번 항목 관련해서 대표님이 "RLS를 적용 안 하면 서비스에 문제가 있는 것 아니냐"고 재확인을 요청. 다시 조사한 결과 RLS보다 훨씬 근본적인 문제를 발견: `src/lib/firebase.ts`의 Firebase 프로젝트 설정이 전부 데모용 placeholder였고 `.env`에 실제 Firebase 값이 아예 없어서, **이메일/비밀번호 회원가입·로그인은 실제로 에러가 떴고, 구글 로그인은 인증 실패 시 조용히 하드코딩된 가짜 Pro 계정으로 로그인되는** 상태였음. 이 상태에서는 RLS를 적용하든 안 하든 인증 자체가 허수였음.
- **결정**: 대표님과 상의 후, 새 Firebase 프로젝트를 만들어 연동하는 대신 **이미 실제로 쓰고 있는 Supabase 하나로 인증을 통합**하기로 결정 (Plan 모드로 설계 문서 작성 후 승인받아 진행).
- **조치 사항**:
  - `src/contexts/AuthContext.tsx` 전면 재작성: Firebase Auth 대신 Supabase Auth(`signInWithPassword`, `signUp`, `signInWithOAuth('google')`, `onAuthStateChange`) 사용. **인증 실패 시 가짜 Pro 계정으로 로그인되던 3단계 폴백 로직 완전 제거** (보안 수정).
  - Firestore 이중 저장 로직 제거 — Supabase `users` 테이블이 회원 정보의 단일 소스가 됨.
  - `App.tsx`, `AuthModal.tsx`: Supabase User 객체 형태(`.id`, `.user_metadata`)에 맞춰 필드 접근 조정.
  - `src/lib/firebase.ts`, `src/lib/firestore.ts` 삭제, `package.json`에서 `firebase` 의존성 제거 (번들 크기도 2.28MB → 1.49MB로 감소하는 부수 효과).
  - `server/db/schema.sql`: `users` 테이블에 `is_admin BOOLEAN DEFAULT FALSE` 컬럼 추가 (기존 배포 DB에도 안전하게 적용되는 `ADD COLUMN IF NOT EXISTS` 포함).

  - `src/services/supabaseService.ts`의 `upsertUserProfileDB`가 `auth_uid`(Supabase 세션의 `auth.uid()`)도 함께 저장하도록 수정.

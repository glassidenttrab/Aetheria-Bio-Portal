- **배경 및 원인**: 
  - Enterprise B2B 콘솔 모달을 열었을 때, 최상위 Overlay의 CSS 레이아웃(`display: flex; align-items: center;`) 한계로 인해, 디바이스 뷰포트 높이가 낮거나 스크롤이 발생할 때 모달의 상단 헤더 타이틀과 닫기(`X`) 버튼이 뷰포트 상단 영역(Negative Y offset) 밖으로 넘어가 잘려 보이지 않는 버그가 지적됨.

  - **효과**: 넉넉한 뷰포트에서는 화면 수직 중앙에 예쁘게 배치되고, 좁은 화면이나 오버플로우 발생 시에는 상단 32px 위치에 안전하게 고정되어 헤더 타이틀 및 닫기 버튼이 1px도 잘리지 않도록 레이아웃 완벽 개선.

### 16. 결제 성공 직후 플랜이 다시 'free'로 리셋되는 심각한 버그 수정
- **배경**: 대표님이 PayPal 샌드박스로 Pro($490) 결제 테스트를 했는데, 마스터 콘솔에서 구독 플랜이 `free`로, 잔여 쿼리는 Pro 쿼터인 `30`회로 나오는 모순된 상태를 발견해 제보.
- **원인**: `upsertUserProfileDB()`가 호출부에서 넘기지 않은 필드까지 항상 기본값(plan은 무조건 `'free'`, queries_remaining은 무조건 `3` 등)으로 채워서 매번 행 전체를 덮어쓰고 있었음. 결제 성공 시 `recordSubscriptionDB()`가 plan을 `'pro'`로 정상 반영한 직후, `SaaSPlatformView.tsx`의 쿼터 리셋 로직(`resolveQuota`)이 "새 플랜이니 쿼터 갱신"이라며 `queriesRemaining`만 담아 부분 업데이트를 호출했는데, 이때 `plan`을 안 넘겼다는 이유로 DB의 plan이 조용히 다시 `'free'`로 되돌아갔음 (queries_remaining은 이 호출에서 명시적으로 30을 넘겼으므로 30으로 남음) — 정확히 제보된 증상과 일치.
- **조치 사항**:
  - `upsertUserProfileDB()`를 호출부가 **실제로 넘긴 필드만** upsert 대상에 포함하도록 수정 (넘기지 않은 필드는 기존 DB 값을 그대로 유지). 신규 가입으로 행이 없을 때는 DB 컬럼 자체의 DEFAULT 값이 자연스럽게 적용됨.
